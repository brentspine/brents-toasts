# 2.1.2 - 2026-07-23

## Added

- **`ToastButton` and `ToastButtonStep` types** exported from the library for building custom multi-step button flows.
- **`Toasts.confirmButton()`** / **`ToastBuilder.withConfirmButton()`** — ready-made confirm-before-action button ("Delete" → "Are you sure?" → runs callback → "Done" → reverts). Auto-reverts the confirm step if left untouched, disables itself while async actions are pending.
- **`Toasts.detailsCopyButton()`** — opt-in copy button for detail items (replaces auto-added copy buttons). Takes `text`, `label`, `copiedLabel`, and `className` parameters.
- **`Toasts.stepButton()`** / **`ToastBuilder.withStepButton()`** — general-purpose multi-step button primitive for custom click-driven flows. Each step has its own label, optional `onClick`, optional auto-revert timer, and optional per-step class names. `onClick` can return `false` to stay on that step or a `Promise` to disable the button until it settles.

## Changed

- **Details copy behavior is now opt-in.** Removed automatic "Copy" buttons on detail items (`detailsCopyable` and `detailsCopyableSingle` options removed). Push `toasts.detailsCopyButton(value)` into a detail item's `buttons` array to add a copy button to that specific item.
- **`ToastDetailItem.buttons`** now documented as the place to add custom actions (including copy buttons), replacing the auto-added copy button behavior.
- **Close button visual refinement:** the accent bar no longer grows on hover; instead, closable toasts reserve trailing margin space that collapses when the close affordance appears, keeping the overall toast width stable.

## Fixed

- Step buttons (`confirmButton()`, `detailsCopyButton()`, `stepButton()`) now properly disable themselves while async `onClick` handlers are pending, preventing double-clicks on slow actions.
