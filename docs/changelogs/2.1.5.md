# 2.1.5 - 2026-07-23

## Added

- **`data` option** (`ToastOptions`/`ToastBuilder.withData()`) — attach arbitrary per-toast data (e.g. an item to restore for an "Undo" button), readable later via `getToastData(id)` so a single shared handler can look up what each toast represents without needing a closure per toast.
- **`getToastTimer(id)`** — read the current countdown state as `{ duration, remaining, paused }` or `null` if the toast doesn't exist or is sticky.
- **`getToastData(id)` / `setToastData(id, data)`** — read back or update per-toast data after creation (e.g. once async data resolves).
- Demo: "More examples" section with a shared undo handler demo combining `data`, `getToastTimer()`, and `getToastData()` across multiple toasts.

## Changed

- **Details toggle** now calls `resetToastTimer()` when opened, so a toast won't disappear while the user is reading its expanded details (consistent with `confirmButton()` and the new `detailsCopyButton()` behavior).
- **`detailsCopyButton()`** now calls `resetToastTimer()` on click, preventing the "Copied!" flash from being cut short by auto-dismiss.
